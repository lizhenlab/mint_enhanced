# 批量比较与数据集评测

入口为“数据 → 批量比较”和“评测与质检 → 数据集评测”。两个入口共用输入选择、推理协议、提交前检查、持久任务和结果索引。前者可以处理没有参考标注的视频；后者要求每个输入都有明确的参考标注。

## 批次与单个比较的关系

选择 N 个视频或 LeRobot Episode、M 个算法变体后，会建立 N 个独立比较，每个比较包含所选算法的结果。相同输入的算法共享解码后的画面与帧时间轴；每个视频的结果、日志和恢复状态独立保存。批次负责组织和跟踪这些比较，不把多个视频拼成一个长视频，也不把它们的三维结果合并。

批次协调器逐个推进输入；当前输入中的算法可以按现有调度器获得 GPU。MINT、ACE 等算法在支持的阶段可以使用多卡，HaWoR 的连续 SLAM 等阶段仍具有顺序依赖。因此，勾选八张卡并不意味着所有视频和算法会同时占满八张卡。GPU 继续遵循平台的共享资源和负载准入策略。

最多帧数留空时保留所选输入的完整可用范围，没有默认 450 帧截断。目标 FPS 为 0 时保留源帧率；改成其他 FPS 会明确改变抽帧时间轴。起始帧和最多帧数应用到每个所选输入，提交前检查会分别展示实际可处理的范围。LeRobot 的起始范围在 Episode 内解释，不能越过该 Episode。

## 三步创建批次

1. **核对输入。** 从“服务器视频”或“LeRobot Episode”选择输入，再进入批量比较。清单列出每个条目的来源、类型和参考标注情况，可以逐条移除；分页只改变当前显示，不删除其他页的选中项。提交前应检查同名文件是否来自预期目录。
2. **设置推理条件。** 选择视角、目标 FPS、起始帧、最多帧数，再明确参考标注与相机内参策略。算法、检查点和各算法的高级参数在独立区域设置。
3. **检查并提交。** 先进行预检，阅读汇总和逐输入结果，确认帧数、视角、内参、参考标注、警告及预计资源。预检不会启动推理；只有显式点击提交才创建后台批次。任何输入、算法或协议变更都会使原预检失效，需要重新检查。

预检失败时不能提交整批任务。失败原因会对应到具体输入，便于修正范围、补充标定、移除不适用条目，或更换支持该输入长度的算法。预检通过只代表输入和运行条件可接纳，不代表算法一定会在长任务中成功，也不证明结果质量。

## 参考标注与内参分别声明

参考标注用于计算误差，相机内参可以作为算法的额外输入，两者不应由同一个开关隐式控制。

| 参考策略 | 含义 | 适用入口 |
|---|---|---|
| 有标注时附加 | 逐输入读取已明确接入且可用的参考；没有参考的条目仍做推理 | 批量比较 |
| 不附加参考 | 只生成算法结果和对照展示，不计算该输入的 GT 误差 | 批量比较 |
| 必须有参考 | 每个条目都必须有有效的显式参考，缺失时预检失败 | 数据集评测；批量比较也可严格使用 |

普通视频不因进入“数据集评测”就自动获得 GT。LeRobot 标注或显式导入的参考仍需符合平台的帧映射、坐标、单位与监督类型要求；存在标注文件不等于所有帧、所有手都具有有效标注。评测报告区分有效计数、覆盖、失败和不可评分输入。

| 内参策略 | 含义 |
|---|---|
| 不提供已知内参 | 忽略输入中可用的已知标定作为算法输入，保留算法自身的估计或默认路径 |
| 使用各输入自己的数据集内参 | 每个 Episode 使用其自身已验证的针孔标定；缺少或不支持的标定会在预检中报告 |
| 统一手动标定 | 显式填写一份标定，并确认它适用于所有所选输入；每个输入仍要通过像素网格检查 |

三种内参策略互斥。统一手动标定不会被数据集元数据悄悄覆盖，也不能只因某一个输入可用就被默认推广到全部输入。来自不同相机或不同分辨率的视频应分别提供正确标定，或拆成不同批次。

已知标定不改变算法自身能力边界：ACE K-given 必须获得内参；HaWoR 在提供标定时使用该标定；MINT 仍走自身相机 / FoV 预测，ACE K-free 仍预测内参。比较时应结合实际内参来源解释结果，不能把相同视频理解为所有算法获得了完全相同的额外信息。

## 草稿、冻结协议与结果

创建表单是尚未提交的草稿。已创建批次保存当次的输入身份、算法变体与检查点、帧选择、视角、标注和标定条件；结果区单独展示这份冻结协议。之后修改草稿不会改变正在运行或已经完成的批次。

结果汇总分别统计完成、部分完成、失败、取消和等待中的条目，分页查看每个子比较。点击子比较可进入已有的联动视图、日志、几何下载和单项诊断。批量比较的报告主要组织结果；数据集评测进一步报告标准几何误差、有效覆盖和失败输入。该协议不等于自动复现每个公开数据集论文中的全部官方 benchmark 设置。

取消批次会停止后续输入，并仅取消归该批次独占的运行任务。已完成结果会保留；其他比较复用的共享运行不应被连带终止。恢复时复用完整结果，继续失败、部分完成、取消或中断的条目；输入身份或算法版本变化时应新建批次，避免把不同实验条件混在同一份报告中。

JSON 报告可用于追溯完整协议和输入状态；评测另提供 CSV。界面显示的“处理完成”不等于所有条目成功，应同时检查完成数、失败数、部分完成数和有效参考覆盖。
