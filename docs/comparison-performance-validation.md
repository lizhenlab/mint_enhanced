# 多卡执行与全视频性能验证（2026-10-30）

增强代码只在 MINT 仓库内。ACE 和 HaWoR 的源码、模型与虚拟环境作为只读依赖；测试前后源码内容、时间及工作区状态一致。额外扫描 ACE 34,356 个文件、HaWoR 76,925 个文件，未发现本轮测试开始后新增或修改的文件。ACE 原有四处未提交修改保留原样。

## 执行方式

- MINT 保留现有 GPU 窗口调度。ACE 独立 81 帧片段、HaWoR 手部原生 16 帧分组和 Metric3D 关键帧使用持久 GPU 子进程池，最多 8 卡。
- 使用同一物理 GPU UUID 租约；根据可用显存、其他进程负载和任务数量动态启用卡，完成阶段后释放。共享暂停时保留模型以减少冷加载，压力出现时仍允许回收。
- 模型副本启动前检查主机内存，CUDA 子进程具有显存上限、父进程退出回收和独立日志。页面可设置各算法 GPU 上限，显示阶段实际卡数与并发峰值。
- HaWoR 检测跟踪、DROID-SLAM 和世界补全具有顺序依赖，相应阶段保留单卡执行。SLAM 扩容同时处理视频张量、前端下一帧槽位、因子图 damping 与轨迹填充临时槽位。

## 完整 10428 帧输入

测试视频：`/data1/lizhen_dataset/3DVideo_2026-05-13-09-41-33-189.mp4`，左眼 1624×1232，36.0025 FPS，保留全部帧。

8 张 A800 同时运行时，各阶段共享租约。本次长视频手部测试期间有一张卡用于 SLAM，因此实际并发为 7；另一次 720 帧 ACE 测试实际使用 8 卡，完整生成 720 帧。机器同期存在其他 GPU 任务，上表是运行观测，不是隔离硬件上的严格速度基准。

输入 RGB 的每个像素、源帧索引和 PTS 与原缓存逐项相同。新预览为 1280×972、10428 帧，模型输入保持全分辨率。解码结果只在全部写入并完成持久刷新后发布。

## 数值一致性与全流程

ACE 131 个片段的姿态、形状、平移、存在性及直接预测关节逐元素相同。使用与正式服务相同的 OMP/MKL 四线程进行 CPU 后处理时，标准 3D 关节差为 0，最大投影差约 0.000793 像素；差异来自原生 CPU 最小二乘内参拟合的末位浮点舍入。原生网格内参最大差约 0.000610 像素。

HaWoR 全片姿态、形状和平移参数逐元素相同。GPU 批量光栅化掩码有 119 个像素不同，均在一像素边界内，占手部前景并集约 2.73e-7；没有把它记为掩码逐像素完全相同。此项是适配数值验证，不是模型精度评测。

HaWoR Full 复用了已经验证的原输入、检测与手部阶段，然后完整运行长视频世界阶段：10428 帧全部完成，758 个关键帧，缓冲从 512 扩到 1024。SLAM 约 1495 秒，Metric3D 实际 8 卡约 54 秒，世界补全约 24 秒；结果同时具备相机系和世界系。复用阶段未计作冷启动提速。SLAM 的长序列全局优化仍是主要顺序瓶颈。
