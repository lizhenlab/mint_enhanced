# 完整长视频处理

命令行推理和 Viewer 默认处理视频全部时间范围，不再设置 450 帧或 160 帧的默认截断。
裸视频默认保留所有源帧及源视频报告的帧率；只有显式指定 `--max-frames` 或目标 FPS 时才截取或抽帧。

## 处理流程

```text
原始 MP4 → 按字节预算分块解码 → RGB 磁盘缓存
       → 最多 8 卡动态共享队列 → 当前窗口的分块归一化/缩放 → 模型前向
       → 按原始顺序拼接相机和双手 → 全序列平滑 → 分批 MANO → 完整视频导出
```

原实现先收集整段原分辨率 RGB，再将整段转成浮点并缩放。对 10428 帧、3248×1232 输入，
RGB 本身约 117 GiB，整段浮点临时数组可能让内存超过 1 TiB。
现在长视频 RGB 使用 `.npy` 内存映射文件，解码块写完后刷盘并释放映射页；
每张 GPU 的工作线程只预处理当前窗口，并对原分辨率浮点转换再次按内存预算分块。
归一化、插值方式、模型输入分辨率和原有窗口拼接公式保持一致。

短视频直接写入预分配内存数组，避免列表堆积后再拼接造成双份 RGB 分配。
长视频不再建立全序列浮点输入。MANO 几何计算也按小批处理，视频编码逐帧写入。
资源占用主要由模型副本数、窗口大小、解码/预处理预算和结果数据决定；磁盘缓存大小随视频长度增加。
操作系统仍可能保留可回收的文件页缓存。

## 使用

```bash
./run_mint.sh viewer --host 127.0.0.1 --port 8011 \
  --devices shared --no-open --full-max-frames 32
```

前端选择视频后，普通单目视频保持 `Video view / 视频视角 = Full`。
对于等宽左右并排双目视频，选择 `Left eye / 左眼` 或 `Right eye / 右眼`，然后点击开始推理。
视角选择只改变空间裁剪，完整时间范围和全部源帧保留。LeRobot 真值样例使用其标注视角。
左右眼分别登记为独立输入条目，各自的 RGB、预测和渲染缓存不会混用。

命令行示例（双目左眼）：

```bash
./run_mint.sh infer --input /path/to/stereo_video.mp4 \
  --checkpoint checkpoints/model.safetensors \
  --output artifacts/full_video_left --devices shared \
  --video-view left --target-fps 0 --camera-mode max_chunked
```

不需要手动切成互相独立的短视频。窗口仍在同一序列中依次拼接，最终结果覆盖所有输入帧。
NPZ 保存 `source_frame_indices` 和 `fps`；`summary.json` 记录源帧数、首末源帧、视角、帧率和帧缓存位置。
`Max Chunked` 中的 32 帧是每次模型前向的窗口大小，不是每个视频的总帧数限制。
`Full` 仍有单次前向安全上限；原生 `Streaming` 的 KV 缓存会随长度增长，长视频优先使用 `Max Chunked`。

## 缓存与资源配置

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `MINT_FRAME_CACHE_DIR` | 项目 `.cache/video-frames` | 长视频 RGB 磁盘缓存，使用空闲空间充足的磁盘 |
| `MINT_FRAME_MEMORY_MIB` | `256` | 小于该大小时用内存，否则使用磁盘映射；不截断视频 |
| `MINT_DECODE_MEMORY_MIB` | `128` | 单次原分辨率解码的近似字节预算，最少一帧 |
| `MINT_PREPROCESS_MEMORY_MIB` | `256` | 每个工作线程进行原分辨率浮点转换的近似临时预算，最少一帧 |
| `MINT_MANO_BATCH_SIZE` | `128` | MANO 单批帧数 |

GPU 共享、显存预算、负载退让和目标工作占空比沿用[动态 GPU 调度](gpu-scheduling.md)。
默认关闭 `expandable_segments`，避免当前服务器驱动在多卡动态加载/回收时出现 VMM 映射错误；每个工作线程同时显式进入自己的 CUDA 设备上下文。
同一源文件、帧索引和视角会重用完成的 RGB 缓存；源文件大小或修改时间变化后重新解码。
缓存写入使用文件锁及临时文件，只有完整解码结束后才发布；取消或失败时不将半成品当作可用缓存。
磁盘不足时会报告所需空间及缓存位置，不会偷偷截短视频。

左右双目原片只缓存一只眼时，空间约为整幅 RGB 的一半。
示例 10428 帧、单眼 1624×1232 RGB 约 58 GiB，需要预留额外空间给 MP4 和其他结果。
缓存包含解码后的原始图像，应保存在合适的私人目录；完成的缓存不会随一次任务结束自动删除。
