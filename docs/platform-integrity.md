# 平台功能完整性修复与兼容说明

本轮围绕现有数据、推理、结果组合、评测、训练和专项工具修复协议与交互问题，不更换默认模型。主入口仍为 `/compare`，MINT 专业诊断为 `/diagnostics`。

## 数据和结果

- LeRobot 参考内参优先读取逐帧像素 K；缺少 K 时按每帧 FoV 重建。`cam_fov` 使用 `[vertical, horizontal]`，旧 `fov` 使用 `[horizontal, vertical]`。
- K-given 只接受所选片段中保持不变的标定，避免把变化的内参静默压成首帧常量。GT 仍可保留逐帧变化的内参。
- 原生数据的帧映射随发布版本冻结。旧版本按内容核验映射，不改写已有完成标记。
- 相机外参组合明确标记为派生结果，即使使用声明 GT 的手部，也不把组合后的预测世界相机自动当作 GT。原始手部几何与 K 保持不变；新组合使用独立版本身份，历史结果不改写。
- 帧数、像素网格和 GPU 数先验证为整数，拒绝小数截断或把布尔值当数字。无符号源帧索引也必须严格递增。

## 评测

汇总从提交时冻结的算法集合建立：未创建成功的输入、缺失的算法结果和参考失败都会保留在尝试/失败计数中。有有效 GT 的失败保留在覆盖率分母中。

任何输入的参考不可评分时，整体 `gt_geometry_coverage` 为空，`unscorable_sequences` 显示数量；`available_reference_geometry_coverage` 仅描述有可用参考的部分。后者不能替代整体覆盖率。CSV 同步保留这两个口径。

## 训练数据与恢复

复核相机数据导出使用训练约定 `[fov_h, fov_w]`。新导出的 `meta/info.json` 和 `source_manifest.json` 声明 `cam_fov_order=height_width`。已知旧版人工复核相机数据缺少该声明时，训练和再次转换会要求从原始复核结果重新导出新版本；不会就地修改旧产物。旧转换版本的来源链同样检查，避免再次转换丢失迁移要求。

相机伪标签、MANO 伪标签及其转换版本都要求显式允许 `allow_pseudo_labels`。复核不改变模型生成标签的性质。

完整检查点必须同时具备模型、优化器、调度器、随机状态、有效步数和一致的文件身份。损坏的标记在曲线中显示不完整，不使整个曲线接口失败；自动续训在 GPU 准入前验证，登记训练模型前再验证。训练仍保持每次尝试固定 world size。

## 交互和专项工具

数据集/序列、工作流、目录和曲线只接收当前选择对应的异步响应。数据未加载或参数在预检期间变化时需要重新核对；批量和渲染提交防重复。目录读取失败、空数据和无可用结果分别显示原因。

渲染在申请 GPU 前核对选定源帧、世界相机和可见手部几何；排队快照过期后不会重新启动已完成或已取消的渲染。检查仅覆盖明确选择的区间。

## 保留范围

长视频完整范围、1–8 卡按阶段调度、多机启动能力及现有六大模块保持可用。HaWoR、ACE 源目录与 `/dataset` 原始数据只读。跨物理服务器与云资源仍需真实环境验收；修复不代表模型精度提升。
